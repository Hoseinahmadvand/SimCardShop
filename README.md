# شماره‌یاب — سایت فروش سیم‌کارت و شماره‌های رند

پروژه‌ای بر پایه **ASP.NET Core 8 (Razor Pages) + EF Core + SQL Server + Tailwind CSS**.

> ✅ **وضعیت فعلی: هر ۴ مرحله تکمیل شد + کاربران متعدد پنل با نقش‌بندی و گزارش فروش هر کاربر.** رابط عمومی سایت، پنل مدیریت (شماره‌ها، سفارش‌ها، کاربران)، سیستم ارسال پیامک تبلیغاتی، تنظیمات سایت، SEO پایه، آمار بازدید/کلیک و محدودسازی امنیتی فرم‌های عمومی — همگی در پروژه موجود است.

---

## کاربران متعدد پنل و گزارش فروش هر کاربر

پنل مدیریت از دو نقش پشتیبانی می‌کند:

- **مدیر (Admin):** دسترسی کامل، شامل مدیریت کاربران و تنظیمات سایت.
- **کارشناس فروش (Staff):** دسترسی به شماره‌ها، سفارش‌ها و پیامک، بدون دسترسی به «کاربران و فروش» و «تنظیمات سایت».

از منوی «کاربران و فروش» (فقط برای نقش مدیر قابل مشاهده) می‌توانید کاربر جدید با ایمیل/رمز عبور اولیه بسازید، حساب‌ها را غیرفعال/فعال یا حذف کنید.

هر سفارشی که در صفحه جزئیات آن به وضعیت «تکمیل شده» تغییر کند، به‌طور خودکار به همان کاربر پنل نسبت داده می‌شود؛ در صورت نیاز می‌توانید فروشنده را از همان صفحه دستی تغییر دهید. جمع فروش و تعداد فروش هر کاربر هم در صفحه «کاربران و فروش» و هم به‌صورت خلاصه («برترین فروشندگان») در داشبورد نمایش داده می‌شود.

## CRM ساده (مشتریان و سرنخ‌ها)

از منوی «مشتریان (CRM)» (برای هر دو نقش مدیر و کارشناس فروش در دسترس است) یک پروفایل ساده برای هر مشتری در دسترس است:

- **ساخت خودکار مشتری**: هر بار که کسی از سایت فرم «خرید شماره» یا «درخواست تماس» را ارسال کند، یک پروفایل مشتری بر اساس شماره موبایل پیدا یا ساخته می‌شود و در تایم‌لاینش ثبت می‌شود. نیازی به کار دستی نیست.
- **افزودن دستی**: از «افزودن مشتری جدید» می‌توان لید تازه (مثلاً از اینستاگرام یا حضوری) را دستی وارد کرد.
- **تایم‌لاین فعالیت‌ها**: یادداشت، تماس، پیامک، سفارش و تغییر وضعیت به ترتیب زمانی نمایش داده می‌شود؛ می‌توان یادداشت/تماس جدید هم مستقیماً از همان صفحه ثبت کرد.
- **وضعیت و پیگیری**: هر مشتری یکی از وضعیت‌های «سرنخ جدید»، «در حال پیگیری»، «مشتری» یا «از دست رفته» را دارد، به یک کارشناس فروش قابل واگذاری است، و می‌توان برایش تاریخ «پیگیری بعدی» تعیین کرد. داشبورد و لیست مشتریان هشدار می‌دهند چند نفر امروز باید پیگیری شوند.
- **اتصال به سفارش‌ها و پیامک**: سفارش‌های هر مشتری در پروفایلش دیده می‌شود؛ دکمه «پیامک» مستقیماً به فرم ارسال پیامک با موبایل همان مشتری پر‌شده می‌رود.

## نصب و اجرا

### ۱. بازیابی پکیج‌های .NET

```bash
dotnet restore
```

### ۲. تنظیم Connection String

فایل `appsettings.Development.json` را باز کنید و مقدار `ConnectionStrings:DefaultConnection` را مطابق سرور SQL خودتان تنظیم کنید. به صورت پیش‌فرض از LocalDB استفاده می‌شود:

```json
"DefaultConnection": "Server=(localdb)\\mssqllocaldb;Database=SimCardShopDb;Trusted_Connection=True;MultipleActiveResultSets=true"
```

### ۳. ساخت دیتابیس

در حال حاضر پروژه از `EnsureCreatedAsync` برای ساخت خودکار جدول‌ها و Seed داده‌های نمونه استفاده می‌کند، پس نیازی به اجرای دستی Migration برای اولین اجرا نیست.

اگر می‌خواهید از EF Core Migrations استفاده کنید (توصیه‌شده برای محیط Production):

```bash
dotnet tool install --global dotnet-ef   # فقط یک‌بار
dotnet ef migrations add InitialCreate
dotnet ef database update
```

و در `Program.cs` خط `EnsureCreatedAsync` را با `context.Database.MigrateAsync()` جایگزین کنید.

### ۴. ساخت استایل‌های Tailwind

```bash
npm install
npm run build:css
```

برای توسعه و مشاهده زنده تغییرات:

```bash
npm run watch:css
```

### ۵. اجرای پروژه

```bash
dotnet run
```

سایت روی آدرسی مشابه `https://localhost:5001` بالا می‌آید.

## اطلاعات ورود Admin (Demo)

هنگام اولین اجرا، به صورت خودکار یک کاربر ادمین نمونه ساخته می‌شود:

| فیلد | مقدار |
|---|---|
| ایمیل | `admin@example.ir` |
| رمز عبور | `Admin@12345` |

⚠️ پیش از انتشار روی سرور واقعی، حتماً این رمز عبور را تغییر دهید (کد مربوطه در `Data/SeedData.cs`).

پنل مدیریت را از مسیر `/Admin/Login` باز کنید. پس از ورود به داشبورد هدایت می‌شوید و از منوی کناری به «مدیریت شماره‌ها» و «مدیریت سفارش‌ها» دسترسی دارید.

## شماره‌های نمونه (Seed)

برای تست فوری، چند شماره نمونه با وضعیت‌ها و قیمت‌های مختلف در دیتابیس درج می‌شود، از جمله:

- `/i/09121234567`
- `/i/09121112233`
- `/i/09200936136`
- `/i/09351234567` (رزرو شده)
- `/i/09901234567`
- `/i/09121001001` (رند آینه‌ای، ویژه)

## نحوه اضافه کردن شماره جدید

از پنل مدیریت وارد شوید (`/Admin/Login`) → «مدیریت شماره‌ها» → «افزودن شماره جدید». فرم شامل شماره، اپراتور، نوع سیم‌کارت، وضعیت کارکرد، نوع رندی، قیمت، درصد تخفیف، وضعیت موجودی و توضیحات است. لینک اختصاصی شماره (`/i/{number}`) و متن آماده SMS از همان لیست با دکمه‌های «کپی لینک» و «کپی متن SMS» در دسترس است.

## نحوه ارسال SMS

از پنل مدیریت → «ارسال پیامک» بروید:

1. در صورت تمایل یک شماره خاص برای تبلیغ انتخاب کنید (فیلدهای `{Number}`، `{Price}` و `{Link}` در متن با اطلاعات آن جایگزین می‌شوند).
2. متن پیامک را بنویسید یا از یک قالب آماده («قالب‌های پیامک») شروع کنید.
3. گیرندگان را به‌صورت دستی (هر خط یک شماره) وارد کنید یا فایل CSV/متنی آپلود کنید.
4. روی «پیش‌نمایش و بررسی» کلیک کنید تا تعداد گیرندگان معتبر، تعداد پیامک تخمینی و متن نهایی را ببینید.
5. پس از تأیید کادر تیک، روی «ارسال پیامک» کلیک کنید.

شماره‌های ثبت‌شده در «لیست عدم ارسال» به‌طور خودکار از هر کمپینی حذف می‌شوند. تاریخچه کامل ارسال‌ها در «تاریخچه پیامک‌ها» قابل مشاهده است.

### اتصال به یک پنل پیامک واقعی

سرویس ارسال در `Services/SmsService.cs` پیاده‌سازی شده و فعلاً در نبود تنظیمات API به‌صورت Mock عمل می‌کند (فقط لاگ می‌گیرد). برای اتصال واقعی:

1. مقادیر `SmsApiUrl`، `SmsApiKey` و `SmsSenderNumber` را در جدول `SiteSettings` پر کنید (فرم تنظیمات در مرحله ۴ اضافه می‌شود؛ فعلاً از طریق دیتابیس قابل تنظیم است).
2. بلوک `TODO` داخل `SmsService.SendAsync` را با فراخوانی HTTP مطابق مستندات پنل پیامک موردنظر جایگزین کنید.

## تنظیم درگاه پرداخت (در دست ساخت)

اتصال درگاه پرداخت در مراحل بعدی به فرآیند خرید (`Pages/SimCardDetails.cshtml.cs`، متد `OnPostBuyAsync`) اضافه خواهد شد. در حال حاضر سفارش مستقیماً ثبت و شماره به صورت موقت رزرو می‌شود تا کارشناسان دفتر پیگیری تلفنی انجام دهند.

## نکات امنیتی پیاده‌سازی‌شده

- قفل حساب Admin پس از ۵ تلاش ناموفق ورود.
- محدودسازی نرخ درخواست (Rate limiting) بر اساس IP روی فرم‌های خرید و درخواست تماس در صفحه هر شماره.
- جلوگیری از ثبت سفارش تکراری برای همان شماره موبایل در بازه ۱۰ دقیقه‌ای.
- Anti-forgery Token روی تمام فرم‌های POST (رفتار پیش‌فرض Razor Pages).
- هدرهای امنیتی پایه (`X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`).
- پوشه `/Admin` کاملاً پشت نقش `Admin` محافظت‌شده است.

## محدودیت‌های شناخته‌شده / گام‌های بعدی پیشنهادی

- درگاه پرداخت واقعی و پنل پیامک واقعی هنوز وصل نشده‌اند (محل دقیق TODO مشخص است).
- برای مقیاس بزرگ، بهتر است `EnsureCreatedAsync` با EF Core Migrations واقعی جایگزین شود.
- تست خودکار (Unit/Integration Test) در این تحویل گنجانده نشده و پیشنهاد می‌شود قبل از انتشار اضافه شود.
